## 🎯 Qué se pedía

Instalar en el ordenador de casa las herramientas necesarias (Obsidian, Git y OBS), generar una nueva clave SSH exclusiva para este equipo y vincularla a GitHub. Finalmente, reconstruir de forma local (fuera de OneDrive) la estructura de carpetas de la bóveda clonando tanto el repositorio de apuntes como los tres de prácticas desde GitHub.

## ⌨️ Comandos y pasos importantes

- `sudo apt install git` — Instala Git en el equipo local (o mediante su instalador oficial en Windows).
- `git --version` — Comprueba que Git se ha instalado correctamente y muestra su versión.
- `ssh-keygen -t ed25519 -C "tu-correo-de-github"` — Genera un nuevo par de claves SSH (pública y privada) de tipo ed25519 para el equipo de casa.
- `cat ~/.ssh/id_ed25519.pub` — Muestra por pantalla la clave pública SSH para copiarla y añadirla en la configuración de GitHub.
- `git config --global user.name "Tu Nombre"` — Configura el nombre de usuario global en Git.
- `git config --global user.email "tu-correo-de-github"` — Configura el correo electrónico global en Git.
- `ssh -T git@github.com` — Verifica que la conexión y autenticación SSH con GitHub funcionan correctamente.
- `mkdir -p RUTA_SOR/Boveda_SOR/00_Apuntes` — Crea la carpeta local para los apuntes dentro de la estructura de la bóveda.
- `mkdir -p RUTA_SOR/Boveda_SOR/01_Practicas` — Crea la carpeta local para las prácticas dentro de la estructura de la bóveda.
- `pwd` — Comprueba el directorio actual en la terminal antes de clonar.
- `git clone git@github.com:TU-USUARIO/apuntes-sor-t1.git Trimestre_1` — Clona el repositorio de apuntes dentro de `00_Apuntes` renombrando la carpeta resultante a `Trimestre_1`.
- `git clone git@github.com:TU-USUARIO/bloque-0-prerequisitos.git B0_Prerrequisitos` — Clona el repositorio de prácticas del Bloque 0 dentro de `01_Practicas` (junto con sus homólogos para `B1_Entorno` y `B2_Ubuntu_Local`).

## 🤔 Respuestas a las preguntas

1. **¿Por qué clonas desde GitHub en vez de copiar con pendrive?**
   Porque en GitHub está la versión buena y actualizada de todo el trabajo del centro; clonar directamente desde ahí garantiza que la copia de casa sea exactamente igual a la del aula y evita conflictos de sincronización o versiones desfasadas.
2. **¿Por qué generas una clave SSH nueva en casa?**
   Porque las claves privadas son únicas por dispositivo y nunca deben copiarse de un ordenador a otro. Es normal y seguro tener varias claves asociadas a una misma cuenta de GitHub (una para el equipo del centro y otra para el de casa).
3. **¿Dónde NO debe estar la bóveda?**
   No debe estar dentro de carpetas sincronizadas con **OneDrive** (como una carpeta *Documentos* con el icono de nube), ya que Git y OneDrive entran en conflicto y generan archivos duplicados. Debe estar en una carpeta local fuera de OneDrive.
