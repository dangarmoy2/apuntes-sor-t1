## 🎯 Qué se pedía

Practicar la recuperación ante distintos tipos de borrado en repositorios Git mediante tres retos progresivos: restaurar archivos borrados localmente sin conexión (`git restore .`), reconstruir una carpeta de repositorio borrada por completo clonando de nuevo desde GitHub, y comprobar que los cambios locales sin `push` se pierden definitivamente al borrar la carpeta..

## ⌨️ Comandos y pasos importantes

- `pwd` — Comprueba el directorio actual en la terminal antes de ejecutar comandos de Git.
- `git status` — Muestra el estado del repositorio local (por ejemplo, archivos marcados como `D` / *deleted*, si el árbol está limpio o si no es un repositorio Git).
- `git restore .` — Restaura todos los archivos modificados o borrados desde la ubicación actual hacia abajo dejándolos como en el último commit (sin necesidad de Internet).
- `git clone git@github.com:TU-USUARIO/bloque-2-ubuntu-local.git B2_Ubuntu_Local` — Vuelve a descargar desde GitHub el repositorio completo (con su historial) tras haber borrado la carpeta local.
- `git log --oneline` — Muestra el historial resumido de commits en una línea por commit para comprobar que el historial volvió al clonar.
- `git clone https://github.com/TU-USUARIO/bloque-1-entorno.git B1_Entorno` — Clona de nuevo el repositorio del Bloque 1 por HTTPS tras borrar la carpeta local (sin recuperar lo que nunca se subió a GitHub).

## 🚩 Qué me ha fallado y cómo lo he resuelto

- **Error provocado en el Reto 2 (al consultar el estado tras borrar la carpeta del repositorio):** Al ejecutar `git status` desde `01_Practicas/` tras borrar `B2_Ubuntu_Local`, Git devolvió el mensaje literal:
  `fatal: not a git repository (or any of the parent directories): .git`
- **Cómo lo resolví:** Al haberse borrado la carpeta completa y con ella su carpeta oculta `.git`, no se podía usar `git restore`; lo resolví clonando de nuevo el repositorio desde GitHub dentro de `01_Practicas/`.
- **Pérdida intencionada en el Reto 3:** Al borrar `B1_Entorno` habiendo creado `MIS_NOTAS.md` sin hacer `commit` ni `push`, el archivo no volvió tras clonar porque nunca salió de esa carpeta local; la única forma de evitar perder trabajo propio es hacer `commit` y `push` al terminar cada sesión.

## 🤔 Respuestas a las preguntas

1. **¿Por qué el Reto 1 se arregla sin Internet y el Reto 2 no? Contéstalo diciendo dónde estaba guardado lo que recuperaste en cada caso.**
   En el Reto 1 se arregla sin Internet porque lo que recuperaste estaba guardado en tu propio ordenador dentro de la carpeta oculta `.git` (el historial local dentro de `B2_Ubuntu_Local`). En el Reto 2 ya no sirve porque, al borrar la carpeta entera, borraste también `.git` con el historial, así que lo único que quedaba estaba fuera de tu equipo, en GitHub, y hubo que volver a clonar.
2. **En el Reto 3 el repositorio era tuyo y aun así perdiste las notas. ¿Qué faltó?**
   Faltó hacer `commit` y `push` antes de borrar la carpeta (es decir, guardar el cambio en el historial y subirlo a GitHub). Que el repositorio sea tuyo te da permiso para subir cambios, pero no suben solos si no haces `push`.
3. **Un compañero anota cosas en su carpeta de prácticas del aula y no entiende por qué en casa no le salen. Explícaselo en dos frases.**
   Si no hace `commit` y `push` en el ordenador del aula antes de irse, sus anotaciones nunca salen de ese equipo y no llegan a GitHub. Al abrir su copia en casa (o hacer `pull`), GitHub no tiene esos cambios porque nunca se subieron desde el aula.
4. **Resumen de la fase (Paso 5): ¿Por qué el Reto 2 no se arregla igual que el Reto 1, y por qué en el Reto 3 no vuelve todo?**
   El Reto 2 no se arregla con `git restore .` como el Reto 1 porque al borrar toda la carpeta se destruyó también `.git` (el historial local) y hay que volver a clonar desde GitHub. En el Reto 3 no vuelve todo porque `MIS_NOTAS.md` nunca se subió a GitHub mediante `push`, por lo que al borrar la carpeta local se perdió para siempre, mientras que lo que sí estaba en GitHub volvió intacto.
