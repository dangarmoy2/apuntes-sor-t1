## 🎯 Qué se pedía

Dominar y poner en práctica el ciclo diario de sincronización con Git (`pull` al empezar a trabajar y `commit` + `push` al terminar) entre el ordenador de casa y el del centro. Además, comprender que este ciclo debe aplicarse individualmente en cada repositorio que se modifique ese día y por qué la bóveda debe mantenerse fuera de OneDrive para evitar conflictos.

## ⌨️ Comandos y pasos importantes

- `pwd` — Comprueba la ruta del directorio actual en la terminal para asegurarnos de estar dentro del repositorio correcto (por ejemplo, `.../Boveda_SOR/00_Apuntes/Trimestre_1`).
- `git pull` — Descarga y fusiona desde GitHub los últimos cambios realizados desde el otro equipo antes de empezar a trabajar.
- `git add .` — Prepara todos los archivos modificados o nuevos en el repositorio local para ser guardados en el historial.
- `git commit -m "Fase 0.5.2: apuntes escritos desde casa"` — Guarda los cambios preparados en el repositorio local con un mensaje descriptivo.
- `git push` — Sube los commits locales a GitHub para que queden disponibles desde cualquier otro equipo.

## 🤔 Respuestas a las preguntas

1. **¿Por qué NO se mete la bóveda en OneDrive si usamos Git?**
   Porque OneDrive y Git son dos sistemas de sincronización que compiten por los mismos archivos. OneDrive puede sincronizar a medias la carpeta oculta `.git` y corromper el historial, además de generar archivos duplicados en conflicto (`fichero-MiPC.md`) y anular el propósito de `git pull`.
2. **Escribe el ciclo diario de tres pasos.**
   3. **Al llegar al ordenador (empezar):** `git pull` (para bajar lo último del otro equipo).
   4. **Durante el trabajo:** Editar o crear entradas en Obsidian.
   5. **Antes de irse (terminar):** `git add .`, `git commit -m "mensaje"` y `git push` (para subir los cambios a GitHub).
6. **¿Qué problema puede aparecer si olvidas el pull al empezar?**
   Puede producirse un error de conflicto (`CONFLICT`) al intentar sincronizar porque Git detecta que un mismo archivo se ha modificado en dos sitios distintos sin haber integrado antes los cambios previos, por lo que no sabe qué versión es la válida.
